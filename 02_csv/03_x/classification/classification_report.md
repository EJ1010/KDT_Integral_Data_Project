# 치이카와 X 전체 분류 보고

- 기준 버전: v1. 2026-10-28에 시험 분류 규칙을 승인받은 뒤 적용했다. 라벨 정의는 바꾸지 않았다.
- 기준서: `classification/classification_codebook_v1.md`
- 입력: `typed/x_chiikawa_2022_2026_typed.parquet` 하나만 사용했다.
- 실행: Python 3.11.9, pandas 3.0.3, pyarrow 24.0.0, `classification/classify_x_posts.py`

## 1. 처리 범위

| 구분 | 건수 |
| --- | --- |
| 입력 게시물 | 5,000 |
| 시험 100건 수동 판정 유지 | 100 |
| 같은 기준서의 문맥 규칙으로 분류 | 4,900 |
| 결과 행 | 5,000 |
| 추가 확인 파일로 뺀 행 | 1,627 |

게시물을 삭제하지 않았다. 검색 키워드, 좋아요, 조회수, 계정 이름으로 캐릭터나 구매를 추정하지 않았다. 이미지와 외부 링크는 열지 않았다.

4,900건은 본문 문장 단위로 형태와 행동을 짝지었다. 한 문장에 갈래가 여럿이면 전부 곱하지 않고 연결을 확인 필요로 남겼다. 시험 100건에 같은 규칙을 적용해 보면 캐릭터 집합이 같은 글 90건, 형태 82건, 행동 81건이었다. 저장된 100건은 그 규칙 결과가 아니라 이미 읽어 둔 수동 판정이다.

기준서에 없는 이름은 라벨로 만들지 않았다. 해당 글은 보류 후보로 남겼다.

## 2. 결과 파일

| 파일 | 내용 |
| --- | --- |

입력 Parquet의 SHA-256은 실행 후에도 `3bc26b04d91e499fd54799e9599251029b846b200094fdc15b00e315ffd3bbec`이다.

## 6. 확인 필요와 보류

`classification_review_required.csv`는 1,627행이다. 확인 필요 1,538건, 미언급 4건, 그리고 분류는 되었으나 기준서 밖 표현이 있는 글이 들어 있다.

보류로 센 표현이다. 출현 글 수이며 라벨 수가 아니다.

| 표현 | 글 수 | 처리 |
| --- | --- | --- |
| 아크릴 | 43 | 형태 라벨을 만들지 않음 |
| 데카츠요 | 26 | 개별 캐릭터로 넣지 않음. 통칭 후보 |
| 아노코 | 25 | 캐릭터 라벨을 만들지 않음 |
| 포카 | 9 | 포토카드 형태 라벨을 만들지 않음 |
| 오데 | 6 | 오다이바·다녀오다와 구분한 뒤에도 라벨을 만들지 않음 |

이 이름들을 v1에 넣으려면 정의 변경안이 필요하다. 이번 파일에는 넣지 않았다.

확인 필요가 많은 다른 이유는 본문만으로 「치이카와」가 작품인지 주인공인지 안 갈리는 경우, 사진에만 형태가 있는 경우, 한 문장에 형태와 행동이 여럿이라 짝을 닫지 못한 경우다.

## 7. 한계

- 4,900건은 글을 한 건씩 다시 읽은 결과가 아니라 v1 규칙을 본문에 적용한 결과다. 시험 100건과의 규칙 일치율은 위와 같다.
- 해시태그의 매장명, 다른 작품 이름이 바로 앞에 붙은 상품, 비유는 치이카와 형태로 세지 않도록 막았다. 그래도 문장 규칙이 못 가른 짝은 확인 필요다.
- 일본어 입고·등장 문장은 판매 제안으로 읽도록 규칙을 두었다.
- 주문·결제·유료 뽑기 문장만 구매 완료다. 「사왔」도 구매 완료에 포함했다.
- 이미지로만 알 수 있는 내용은 추정하지 않았다.

## 8. 연결 테이블 제안

지금은 게시물 1행에 JSON 배열로 복수 라벨과 연결을 넣었다. 아래처럼 나누면 집계가 쉬워진다. 테이블은 만들지 않았다. 구조를 확인한 뒤에 분리한다.

| 테이블 | 한 행의 의미 | 주요 열 |
| --- | --- | --- |
| post | 게시물 1건 | post_id, 원본 13열, 판단 상태, 판정 출처 |
| post_series | 작품 라벨 1개 | post_id, series_code |
| post_character | 캐릭터 라벨 1개 | post_id, character_code |
| post_form | 형태 라벨 1개 | post_id, form_code |
| post_behavior | 행동 라벨 1개 | post_id, behavior_code |
| post_link | 형태-행동 짝 1개 | post_id, link_no, form_code, behavior_code, surface |
| post_link_character | 그 짝에 붙은 캐릭터 1명 | post_id, link_no, character_code |

`post_link_character`를 두는 이유는 한 짝에 캐릭터가 여러 명일 수 있어서다. 캐릭터가 없는 상품 라인 짝은 이 테이블에 행이 없다. 방문처럼 형태가 없는 행동은 `post_behavior`에만 있고 `post_link`에는 없다.
